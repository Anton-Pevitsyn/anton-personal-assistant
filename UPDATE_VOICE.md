# Обновление: голосовые сообщения

Замените bot.py и Dockerfile в корне существующего приватного репозитория GitHub.
Не создавайте новый сервис Railway. Сохраните существующие ключи, OWNER_TELEGRAM_ID,
Volume /data и DB_PATH=/data/bot.sqlite3. Схема базы данных не меняется.
Railway должен автоматически собрать новый образ; если запуск не начался, выполните Deploy.

Необязательно: TRANSCRIBE_MODEL=gpt-4o-mini-transcribe (это значение уже используется по умолчанию).
Ключ OpenAI должен разрешать обращение к /v1/audio/transcriptions.

Проверка после Active:
1. Отправьте /start: приветствие должно упоминать голосовые.
2. Отправьте голосовую запись «Запомни: встреча в четверг в десять».
3. Бот покажет распознанный текст и ответит текстом.
4. Спросите текстом «Когда встреча?» — ответ использует ту же историю.
5. Проверьте обычный текстовый запрос.

Принимаются именно голосовые Telegram, не аудиофайлы и не видеосообщения.
Лимит одной записи: 5 минут и 10 МБ. Русский язык задан для распознавания.
Аудио скачивается после проверки владельца, конвертируется в WAV и отправляется
в OpenAI. Временные файлы удаляются и при ошибке. На постоянном диске сохраняется
только текст последних 10 обменов. Ответы голосом и живые звонки не добавлены.
Дополнительные расходы: распознавание речи по тарифу OpenAI.
Локально проверены маршрутизация, ограничения, изоляция доступа и сохранение текста
с имитацией внешних API. Реальный голосовой запрос проверяется после размещения.

Откат: восстановите предыдущие bot.py и Dockerfile из истории GitHub и разверните их.
